# Phase 6: Maintenance, Decay & Hierarchy Implementation Plan
This plan details the implementation of Phase 6 for the Self-Evolving Medical RAG (SERA) system. The goals of Phase 6 are to prevent database bloat, prune cold queries, build hierarchical parent nodes (meta-nodes), and coordinate periodic maintenance.
## User Review Required
> [!IMPORTANT]
> - **Fidelity Bounds & LLM Calls**: Merging similar super-nodes utilizes the LLM synthesis pipeline (`synthesizer.run`) which will execute LLM calls and validation loops. Ensure model accessibility during execution.
> - **Depth Cap Flagging**: Any merge resulting in a hierarchy deeper than `MAX_LINEAGE_DEPTH` (default: 2) will not be auto-merged; it will be pushed to the `manual_review_queue` in SQLite.
> - **ChromaDB Boolean Filtering**: We query the entire `super_nodes` collection and perform filtering (e.g., `in_hierarchy == False`) in Python rather than relying on ChromaDB's where filter for booleans, ensuring compatibility across different ChromaDB local versions.

### Maintenance Layer
#### [NEW] [staleness_checker.py](file:///C:/Users/MONISH/Proj/SERA/app/maintenance/staleness_checker.py)
Implement **SU8 (Soft-Staleness Check)**:
- Fetch all super-nodes from ChromaDB.
- Parse their `source_chunks` metadata (a list of raw chunk IDs).
- Query ChromaDB's `raw_chunks` collection using those IDs.
- Compute the `match_ratio` (number of existing chunks / total source chunks).
- If `match_ratio < 1.0` (meaning some chunks were updated or deleted):
  - Mark `is_stale = True` on the super-node in ChromaDB.
  - Call `sqlite_client.flag_cluster_for_re_synthesis(cluster_id)`.
  - Log a maintenance event of type `'soft_stale'`.
#### [NEW] [decay_scorer.py](file:///C:/Users/MONISH/Proj/SERA/app/maintenance/decay_scorer.py)
Implement **SU3 & SU10 (Half-Life Decay)**:
- Define `compute_exponential_decay(meta, half_life_days)`:
  - Calculate `days_since_last_access = (now - last_accessed).days`.
  - Use formula: `decay_score = min(access_count_sqlite, 10) * exp(-days_since_last_access / half_life_days)`.
- Define `compute_and_apply_decay()`:
  - Fetch all super-nodes from ChromaDB where `type == "super_node"`.
  - For each node, retrieve the authoritative access count (`hit_count`) from SQLite.
  - Calculate decay score using the formula.
  - Update the super-node's metadata in ChromaDB with the new `decay_score` and updated `access_count`.
  - If `decay_score < DECAY_PRUNE_THRESHOLD` (0.05):
    - Delete from ChromaDB.
    - Call `sqlite_client.reset_cluster_after_pruning(super_node_id)`.
    - Log a maintenance event of type `'prune'`.
#### [NEW] [hierarchy_merger.py](file:///C:/Users/MONISH/Proj/SERA/app/maintenance/hierarchy_merger.py)
Implement **SU7 & SU11 (Hierarchy Merger)**:
- Fetch all super-nodes and meta-nodes from ChromaDB.
- Filter in Python: keep only nodes where `in_hierarchy == False` (SU7).
- Limit computation to the top 500 nodes sorted by `hit_count` to ensure performance.
- Compute pairwise cosine similarity of their embeddings.
- Identify pairs with similarity `> HIERARCHY_MERGE_THRESHOLD` (0.88).
- For each qualifying pair (node A, node B) that has not been merged yet:
  - Calculate `merged_depth = max(depth_a, depth_b) + 1`.
  - If `merged_depth > MAX_LINEAGE_DEPTH` (2):
    - Refuse the merge, call `sqlite_client.flag_for_manual_review()`, log event `'depth_cap_refused'`, and continue.
  - **Ground-Truth Re-Synthesis (SU11)**:
    - Get the union of the raw chunk IDs from both nodes: `unioned_ids = list(set(chunks_a + chunks_b))`.
    - Instantiate a `SynthesisJob(cluster_id=None, canonical_query=..., chunk_ids=unioned_raw_ids, hit_count=sum_hits, ...)`
    - Call `synthesizer.run(job)` to run the LLM-judge validation pipeline.
    - Re-classify the newly created super-node as a `meta_node`: set `"type": "meta_node"`, `"children": json.dumps([id_a, id_b])`, `"lineage_depth": merged_depth`, `"in_hierarchy": False`.
    - Set `"in_hierarchy": True` and `"parent_meta_id": meta_id` on both child nodes to prevent future pairings (SU7).
